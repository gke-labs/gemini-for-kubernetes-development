# Training Data Generator

This CLI tool generates training data for fine-tuning Gemini models by pairing agent-generated review drafts (stored in GCS) with actual human reviews from GitHub.

## Architecture

This tool is designed as an offline batch processor (CLI) rather than a real-time Kubernetes service.

*   **Reasoning:**
    *   **Temporal Decoupling:** Agent reviews are generated at time $T_0$, but valuable human reviews appear much later ($T_1$). A real-time service would need complex state management to "wait" for human reviews.
    *   **Efficiency:** Batch processing allows scanning historical data to generate large datasets at once.
    *   **Simplicity:** No need for new CRDs, controllers, or permanent resources in the cluster.

## Usage

```bash
go run cmd/gen-training-data/main.go \
  --gcs-bucket <YOUR_GCS_BUCKET> \
  --github-token <YOUR_GITHUB_TOKEN> \
  --output-file training-data.jsonl
```

Example:
```
export GITHUB_TOKEN=...
export GOOGLE_APPLICATION_CREDENTIALS=bin/key.json
./bin/gen-training-data --gcs-bucket repo-agent-storage --github-token $GITHUB_TOKEN 

ls -l training-data.jsonl
```

## Flags

*   `--gcs-bucket`: (Required) The name of the GCS bucket where `syncer` stores `ReviewSandbox` resources.
*   `--gcs-prefix`: (Optional) Prefix to filter objects in the bucket (e.g., `installation-name/ReviewSandbox/`).
*   `--github-token`: (Required) GitHub Personal Access Token. Defaults to `GITHUB_TOKEN` env var.
*   `--output-file`: (Optional) Path to the output JSONL file. Default: `training-data.jsonl`.

## Output Format

The output is a JSONL file where each line is a JSON object containing:

*   `pr_number`: GitHub PR number.
*   `repo`: Repository name (owner/repo).
*   `pr_url`: Full URL to the PR.
*   `agent_review_draft`: The content of the review generated by the agent (from `ReviewSandbox` annotations).
*   `human_reviews`: A list of reviews submitted by users on GitHub.
*   `pr_state`: Current state of the PR (open, closed, merged).
