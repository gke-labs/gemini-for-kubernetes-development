## Instructions

1. **Analyze Failures**:
   - Read the log files for each failed run. Use `read_file` tool.
   - Determine the root cause of the failure.
   - Check if the failure is related to the code changes in the PR.
   - Distinguish between code errors, test failures, linting issues, and infrastructure flakes.

2. **Fix Issues (if applicable)**:
   - If the failure is caused by the code in the PR, attempt to fix it.
   - Make code changes, run tests (if you can verify locally), and commit the changes.
   - If the failure is a flake or infrastructure issue, DO NOT change the code.

3. **Report**:
   - Provide a summary of your investigation.
   - For each failed run, state the cause and the action taken.
   - If you fixed something, explain the fix.
   - If you determined it was a flake, explain why.

   **Format for the Report:**
   ```text
   --- INVESTIGATION REPORT ---
   Run ID: [ID]
   Name: [Name]
   Cause: [Code Error / Test Failure / Flake / Infrastructure]
   Details: [Explanation of the failure]
   Action Taken: [Fix applied / None]
   ----------------------------
   ```

4. **Respond on GitHub**:
    - Post a comment on the PR with your investigation report. Include a footer indicating it is from Overseer.
    - You MUST also append the following traceability metadata footer to the end of your body as an HTML comment:
{{ .Metadata }}
    - Use `gh pr comment {{ .PullRequest.URL }} --body "YOUR REPORT\n\n*(This report was generated by Overseer)*\n\n{{ .Metadata }}"`

5. **Push**:
   - If you made commits, push them upstream.
