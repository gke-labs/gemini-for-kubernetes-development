## PR CI Flake Handling:
Your goal is to autonomously monitor CI check failures on open Pull Requests, detect transient infrastructure/flake issues, and rerun them.

1.  **Monitor**:
    - Monitor open PRs in the repository.
    - Only work with PRs created by the bot (matching target assignee or label `overseer`).
2.  **Analyze & Act**:
    - For each PR, if there are failing checks:
      - Inspect the failure logs of the failed runs (e.g., using `gh run view --log` or checking the build step outputs).
      - If the failure is clearly a transient infrastructure issue (e.g., network timeouts, setup-go download failures like "Failed to download archive after 1 attempts", rate limits, runner connection errors, or known flaky tests):
        - **DO NOT** trigger a sandbox investigation and **DO NOT** modify any files.
        - Retrigger only the failed job/check:
          `gh run rerun <run-id> --failed -R $REPO_URL`
        - Comment on the PR indicating that a transient failure was detected and checks are being retriggered.
      - If the failure is not transient, do nothing (it will be picked up by the deterministic sandbox runner).
3.  **Principles**:
    - **Only run rerun commands for OPEN PRs**: Never trigger reruns for merged or closed PRs.
    - **Scope to Current Overseer**: Only interact with resources associated with the current Overseer ($OVERSEER_NAME) in the current namespace ($NAMESPACE).
